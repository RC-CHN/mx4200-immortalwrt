# HomeWRK 安装与恢复要点

本记录针对实际确认是 `linksys,homewrk` 的设备。标准 `linksys,mx4300` 有不同分区布局，必须使用自己的镜像。用户界面显示 MX4300 不代表分区已经变成标准 MX4300。

## 写 NAND 前的准备

1. 用 3.3V TTL 的 GND/TX/RX 连接，不接适配器电源线；115200、8N1。记录 U-Boot、设备树、`/proc/mtd` 与出厂信息。不要凭外壳或固件名称选布局。
2. 原机所有分区做离线备份，保存分区表、尺寸、校验和及工具/读取方式。ECC 校正的数据与含 OOB 的原始读取必须区分；不要把不同控制器的原始 OOB 备份盲写回去。备份至少有一份在路由器之外。
3. 验证串口能中断 U-Boot，并实际启动救援系统。原机启动环境、校准区、出厂 MAC 和引导分区不是刷系统时的写入目标。
4. 从 USB 或 TFTP 启动与该板级身份匹配的 initramfs，验证网络、串口、无线及关键模块；保存输出。确认恢复路径可用后才安排 NAND 写入。

已在一台 HomeWRK 上验证的 USB 恢复命令是：

```text
usb start
usbboot 44000000 0
bootm 44000000
```

此例要求 U 盘已按对应镜像的 USB 启动方式准备；不是任意 FAT 分区中复制文件后就能执行。上游的 [首次安装说明](../linksys-first-flash.md) 可作为背景，下载地址和默认配置以实际镜像为准。准备 U 盘时确认磁盘身份，原始写入会覆盖盘内数据。

TFTP 可作为另一条恢复路径，启动环境仅临时设置，不需要为了测试执行 `saveenv`。不要给未知板型套用固定 NAND 偏移或直接运行 `nand erase` / `mtd write`。

## 已安装后的升级

兼容 ImmortalWrt 通常可以在 LAN 中经 LuCI 或 SSH 使用正确机型的 `sysupgrade` 镜像；先检查 SHA-256、设备支持列表，并用系统的镜像检查功能验证。不用 TTL 完成正常升级，但出现早期启动故障时 TTL 仍有用。

保留配置升级保留主机名、密码、Wi-Fi 与网络配置；恢复出厂或不保留配置升级才应用本仓库初始化默认值。第三方系统迁移不保证配置兼容。自定义 kmod 必须来自相同内核配置的配套包，不能因为内核版本号相同就强制安装。

NSS 启动保护可在遗留标记后改用普通无线驱动，但不能恢复无法启动的内核、被破坏的 U-Boot 或校准区。HomeWRK 存在两个固件分区也不等于本项目已经实现自动双内核回滚；没有把未测试的回滚机制当作救援承诺。

## 已完成的实机核对

r5 在一台 HomeWRK 验证了 NAND 中 kernel/root 与待刷镜像逐字节哈希一致、其他 23 个 MTD 分区与原始 ECC 备份一致、LAN 保留配置升级后正常启动。原始备份、环境和设备日志仅在本地私有目录保存，不随开源仓库发布。
